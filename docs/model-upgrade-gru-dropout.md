# 판매량 예측 모델 업그레이드 : 2차 변경안 (GRU 2층 + Dropout 0.2)

- 작성일 : 2026-10-02 / 관련 이슈 : #1 (GRU 2층(32→16)을 기준 모델로 반영)
- 대상 모델 : 2차 변경안 `GRU(32) → Dropout(0.2) → GRU(16)`
- 비교 대상
  - 기존안 : 스켈레톤 LSTM 3층
  - 1차 변경안 : GRU 2층 (32→16). 이슈 #1에서 채택한 모델
  - 참고 : 현재 main의 `scripts/validate_sales_data.py`에 들어 있는 모델 (GRU 2층 + 층마다 Dropout 0.1)
- 실험 : `scripts/validate_sales_data.py`와 같은 평가 절차로 진행했다. 재현 방법은 부록에 있다.
  - seed 42~46 : 네 모델 모두
  - seed 7, 123 : 1차·2차 변경안 (이슈 #1의 확인 절차)
- 원본 결과 : `docs/experiments/model-comparison.jsonl` (24회) / 비교 스크립트 : `scripts/run_experiments.py`

## 요약

- **바꾼 것** : 이슈 #1에서 채택한 1차 변경안의 두 GRU 층 사이에 Dropout 0.2를 넣었다.
  - 파라미터 수(7,009개), 입력(20일 × 11개 피처), 출력, 스케일러, loss(MAE)는 그대로다. 그래서 API 영향은 없다.
- **바꾼 이유** : 1차 변경안을 seed 7개로 돌려 보니 두 가지 문제가 보였다.
  - seed에 따라 드리프트를 겨우 잡았다 (최저 20.3%).
  - 재학습한 모델이 게이트에서 탈락했다 (7번 중 3번).
  - 2차 변경안은 7번 모두 안정적이었다.
- **선택** : 2차 변경안 + 재학습 정책 10 epoch / 학습률 1e-4

| 지표 (seed 42~46, 7, 123 총 7번) | 1차 변경안 | **2차 변경안** |
|---|---|---|
| 검증 WAPE | 8.95% ± 0.22 | **8.83% ± 0.25** |
| 학습-검증 차이 (최대) | +1.53%p | **+0.94%p** |
| 정상 구간 21일 WAPE 최대 (가장 나쁜 seed, 오탐 위험) | 16.9% | **15.4%** |
| 브랜디 드리프트 배치 WAPE (가장 낮은 seed, 감지 여유) | 20.3% (+0.3%p) | **23.7% (+3.7%p)** |
| 10 epoch 재학습 모델 승격 | 4/7 | **7/7** |
| 재학습 후 품절 (승격 반영, 평균 / 중앙값) | 104.7 / 126 | **69.0 / 41** |
| 재학습 후 과잉 입고 (승격된 경우 평균) | 144.5 | 146.0 |

**seed 하나로 판단하면 안 되는 이유**
- seed 42만 보면 1차 변경안의 감지 여유가 더 커 보인다 (브랜디 26.6% vs 24.5%).
- seed를 늘리면 1차 변경안은 20.3%까지 내려가고, 2차 변경안은 23.7% 아래로 내려가지 않는다.
- 2차 변경안의 seed 42 품절(38개)도 7번 중 좋은 쪽 값이다 (중앙값 41개, 평균 69.0개).

**감수한 것** : 참고 모델(현재 main 코드)보다 평소 정확도가 조금 낮고 (8.76% vs 8.58%, seed 42~46), 과잉 입고가 21일에 32개 많다.

## 1. 변경 이력 : 왜 바꿨나

```
기존안      Input(20, 11) → LSTM(32) → LSTM(32) → LSTM(16)                    → Dense(16, relu) → Dense(1)   17,377 params
1차 변경안  Input(20, 11) → GRU(32) → GRU(16)                                 → Dense(16, relu) → Dense(1)    7,009 params
2차 변경안  Input(20, 11) → GRU(32) → Dropout(0.2) → GRU(16)                  → Dense(16, relu) → Dense(1)    7,009 params
참고        Input(20, 11) → GRU(32) → Dropout(0.1) → GRU(16) → Dropout(0.1)   → Dense(16, relu) → Dense(1)    7,009 params
```

| 단계 | 바꾼 내용 | 이전 버전의 문제 | 바꾼 결과 |
|---|---|---|---|
| 기존안 → 1차 변경안 | LSTM 3층을 GRU 2층(32→16)으로 줄였다 | 학습 시퀀스 1,692개에 비해 모델이 컸다 (파라미터 17,377개). seed 44에서 과적합(학습-검증 차이 2.28%p)과 오탐(정상 구간 최대 27.9%)이 났다. | 파라미터가 60% 줄었고, 과적합과 오탐이 사라졌다 (seed 42~46 운영 게이트 5/5). |
| 1차 → 2차 변경안 | 두 GRU 층 사이에 Dropout 0.2를 넣었다 | seed에 따라 감지 여유가 +0.3%p까지 줄었다 (seed 123). 10 epoch 재학습 모델이 7번 중 3번 게이트에서 탈락해, 드리프트 상황에서 기존 모델이 계속 서비스됐다. | 감지 여유가 가장 낮을 때도 +3.7%p다. 재학습 모델은 7번 모두 승격됐고, 재학습 후 품절 중앙값이 126개 → 41개로 줄었다. |

- 1차와 2차 변경안의 차이는 Dropout 한 층뿐이다. 그래서 위 차이는 Dropout에서 나온 것이다.
- Dropout은 재학습(48건)처럼 작은 데이터에 과하게 맞추는 것을 막는 역할을 한 것으로 보인다 (6장).

## 2. 2차 변경안 구조 상세 (기존안 대비)

| 변경 | 내용 | 이유 |
|---|---|---|
| LSTM → GRU | LSTM은 게이트 3개와 별도의 셀 상태를 쓰고, GRU는 게이트 2개로 단순하다. 같은 32유닛이라도 첫 층 파라미터가 5,632개에서 4,320개로 23% 적다. | 입력이 20일로 짧아 LSTM의 긴 기억 능력이 크게 필요하지 않다. |
| 3층 → 2층 | 가운데 LSTM(32) 층을 없앴다. | 샘플 1개당 파라미터가 10.3개에서 4.1개로 줄어 과적합 위험이 낮아진다. |
| Dropout 0.2 | 학습할 때만 첫 GRU 출력의 20%를 무작위로 0으로 만든다. 서빙(추론)할 때는 꺼져 있어서 같은 입력이면 항상 같은 예측이 나온다. | 특정 신호에만 기대지 않게 만든다. 재학습 때도 똑같이 적용된다. |

**그대로 둔 것** : 입력 20일 × 11개 피처, 출력(다음 날 판매 수량), 스케일러(학습 구간에서 한 번만 fit), loss MAE, Adam 1e-3, batch 32, EarlyStopping(patience 15, 최적 가중치 복원), `SEED`, `TRAIN_RATIO`, `WINDOW = 21`, `DRIFT_THRESHOLD = 0.20`. 그래서 `/predict` API와 업로드 CSV 형식에는 영향이 없다.

## 3. AIOps 관점의 평가 기준

| 지표 | 운영에서의 의미 | 통과 기준 |
|---|---|---|
| 검증 WAPE | 평소 예측 정확도 | 7일 전 값을 그대로 쓰는 방법(14.7%)보다 낮을 것 |
| 학습-검증 차이 | 과적합 여부 (학습 데이터만 외웠는지) | 2%p 이하 |
| 정상 구간 21일 WAPE 최대 | 정상인데 드리프트로 판정할 위험 (불필요한 재학습) | 20% 미만 |
| 브랜디 드리프트 배치 WAPE | 실제 변화를 잡아내는지 | 브랜디만 20% 초과 |
| 감지 여유 / 오탐 여유 | 임계값 20%에서 얼마나 떨어져 있는지 (가장 나쁜 seed 기준) | 클수록 안전 |
| 재학습 모델 승격 | 재학습한 모델이 게이트를 통과해 실제로 배포되는지 | 높을수록 운영을 예측하기 쉽다 |
| 재학습 후 품절 / 과잉 입고 | 비즈니스 결과 (다음 21일 브랜디, 사전 입고 = 예측 × 1.1) | 비용 비율로 판단 (5장) |

- 드리프트를 놓치거나 재학습 모델이 탈락하면, 다음 21일 품절이 재학습했을 때보다 약 3~5배 많아진다.

  - 그래서 감지 여유와 승격 안정성은 그 자체로 비즈니스 가치가 있다.
- 정확도가 가장 높은 참고 모델이 감지 여유는 가장 작았다. README가 경고한 "입력을 너무 잘 따라가는 모델은 드리프트를 놓칠 수 있다"와 같은 방향의 결과다.
- 보조 시나리오(바이럴, 변동 폭 확대)는 네 모델 모두 브랜디 WAPE 약 29%로 쉽게 감지해서 차이가 없었다.

- 2차 변경안에서 승격이 5/5로 안정적인 설정은 10 epoch / 1e-4뿐이다. 스켈레톤의 기본값(`FINE_TUNE_EPOCHS = 10`, `FINE_TUNE_LR = 1e-4`)과 같다.

## 5. 왜 2차 변경안을 선택했나

AIOps 루프가 맡은 일의 순서대로 기준을 세웠다.
1. 정상일 때는 조용하고 (오탐 없음)
2. 변화가 오면 반드시 잡고 (드리프트 감지)
3. 재학습한 모델이 예측 가능하게 배포되고 (승격)
4. 그 결과 빨리 회복할 것 (품절 감소)

| 기준 (seed 42~46) | 기존안 | 1차 변경안 | 2차 변경안 | 참고 |
|---|---|---|---|---|
| ① 오탐·과적합 없이 운영 게이트 통과 | 4/5 | 5/5 | 5/5 | 5/5 |
| ② 드리프트 감지 여유 (가장 나쁜 seed) | +1.7%p | +1.8%p | **+3.7%p** | +1.1%p |
| ③ 10 epoch 재학습 모델 승격 | 5/5 | 4/5 | 5/5 | 5/5 |
| ④ 재학습 후 품절 (승격 반영, 중앙값 / 평균) | 57 / 62.8 | 51 / 85.6 | **41** / 71.6 | 66 / 92.0 |

**선택 근거**
- **기존안은 ①에서 제외했다.** 학습할 때마다 seed 운에 따라 과적합되고 오탐하는 모델이 나올 수 있다 (seed 44).
- **1차 변경안(이슈 #1 채택)보다 2차가 ②③④에서 앞선다.**
  - 이슈 확인 seed 7, 123까지 넣은 7번 기준으로는 차이가 더 커진다.
  - 감지 여유 최저 : +0.3%p → +3.7%p
  - 재학습 승격 : 4/7 → 7/7
  - 품절 중앙값 : 126 → 41개
  - 평소 정확도는 비슷하다 (8.95% → 8.83%).
- **참고 모델(현재 main 코드)은 ②가 가장 약하다.** 최악의 seed에서 드리프트를 1.1%p 차이로 겨우 잡았다.
- AIOps에서는 "평소에 조금 더 정확한 모델"보다 "변화를 놓치지 않고, 재학습 결과가 확실히 배포되는 모델"이 더 중요하다고 판단했다.
- **재학습 정책은 10 epoch / 1e-4로 정했다.** 2차 변경안에서 승격이 5/5로 안정적인 유일한 설정이다.

**감수한 것**
- 참고 모델보다 평소 정확도가 0.18%p 낮다 (8.76% vs 8.58%).
- 참고 모델보다 과잉 입고가 21일에 32개 많다 (147개 vs 115개). 1차 변경안과는 비슷하다 (144.5개).
- 재학습 후 품절은 seed에 따라 27~201개로 흔들린다.

**다시 검토할 조건**
- 재고 비용 비교를 위해 `k = 품절 1개의 비용 ÷ 과잉 입고 1개의 비용`으로 둔다.
- 승격이 5/5로 안정적인 조합만 비교하면 이렇다 (비용 = 품절 × k + 과잉).

| k 범위 | 재고 비용이 가장 낮은 조합 |
|---|---|
| k < 2.9 | 참고 + 30 epoch / 1e-3 (k < 0.5면 참고 + 10 epoch) |
| 2.9 ≤ k < 9.2 | 2차 변경안 + 10 epoch / 1e-4 |
| k ≥ 9.2 | 기존안 + 10 epoch / 1e-4 (단, ①에서 제외) |

- 팀이 품절 1개의 비용을 과잉 1개 비용의 2.9배보다 작다고 판단하면, 재고 비용만으로는 참고 모델 + 30 epoch가 더 싸다. 의류는 남은 재고를 할인 처분할 때 손실이 크므로 이 판단은 팀 합의가 필요하다.
- 다른 드리프트 시나리오에서 감지 여유의 순서가 뒤집히면 다시 검토한다.

## 6. 과적합과 과잉 입고는 다른 문제다

### 과적합 (모델 품질 문제)

- **정의** : 학습 데이터를 외워서 처음 보는 데이터에서 성능이 떨어지는 현상이다. 학습 WAPE와 검증 WAPE의 차이로 확인한다.
- **기존안에서 실제로 나타났다** : seed 44에서 차이가 2.28%p로 기준(2%p)을 넘었다. 같은 seed에서 정상 구간 최대 WAPE가 27.9%까지 올라가, 정상 데이터인데도 드리프트로 판정됐다(오탐). 운영에서는 불필요한 재학습이 계속 돌게 된다.
- **해결** : 구조를 바꿔서 해결했다.
  - GRU 2층으로 파라미터를 60% 줄였다 (1차).
  - Dropout 0.2를 넣었다 (2차).
  - EarlyStopping 최적 가중치 복원과 warm start 재학습(낮은 학습률, 짧은 epoch)은 원래 설정을 유지했다.
- **재학습에서의 과적합** : 재학습은 48건이라 과하게 맞추기 쉽다.
  - Dropout이 없는 1차 변경안은 7번 중 3번 재학습 모델이 새 수준을 지나치게 따라가 게이트에서 탈락했다.
  - Dropout을 넣은 2차 변경안은 한 번도 탈락하지 않았다.

### 과잉 입고 (재고 운영 결과)

- **정의** : 사전 입고량(예측 × 1.1, 올림)이 실제 판매보다 많았던 수량의 합이다. 모델 품질 지표가 아니라 재고 정책의 결과다.
- **대부분은 의도된 안전재고다** : 다음 21일 브랜디 실제 판매는 2,539개다. 예측이 완벽해도 10% 안전재고 때문에 과잉 입고가 263개 생긴다. 승격된 재학습 모델의 과잉 입고 평균(모델별 115~228개)은 모두 이보다 적다.
- **모델이 만드는 부분은 수준을 따라가는 속도다** : 브랜디 판매가 빠른 배송 입점으로 일평균 43개 → 112개 → 121개로 뛰었다. 재학습 강도에 따라 모델이 새 수준을 얼마나 따라잡는지가 달라진다.
  - 약하게 따라가면 품절이 늘고 과잉이 준다.
  - 세게 따라가면 품절이 줄고 과잉이 는다.
  - 이건 과적합이 아니라 품절과 과잉을 맞바꾸는 문제이고, 5장의 비용 비율로 판단한다.

## 7. 운영에서 달라지는 점과 남은 작업

| 영역 | 내용 | 상태 |
|---|---|---|
| API | 입출력이 같아서 변경 없음 | 해당 없음 |
| 드리프트 감지 | 임계값 20% 유지. 감지 여유(최악 +3.7%p)와 오탐 여유(최악 +4.6%p) 모두 확보 | 실험 완료 |
| 재학습 정책 | warm start, 10 epoch / 1e-4 유지 | 실험 완료 |
| 승격·롤백 | 승격 시 기존 Production을 Archived로 내려 Production을 1개로 유지 (`archive_existing_versions=True`) | HAIC 서빙에 반영·검증 완료 |
| 재배포 반영 | 승격 직후 서빙 캐시를 비워 다음 요청부터 새 모델이 응답 (`invalidate_cache()`) | HAIC 서빙에 반영·검증 완료 |
| 모델 코드 교체 (이슈 #1) | `scripts/validate_sales_data.py`의 `build_model()`을 2차 변경안으로 바꾸고, README의 기준 모델과 결과표를 갱신 | 이슈 #1에서 확인받은 뒤 진행 |
| 판매량 서빙 이식 | 현재 서빙 앱은 HAIC 주가 모델이다. 판매량 모델로 옮길 때 게이트를 "WAPE 20% 이하 + 기존 모델 이하"로 바꾸고, 플랫폼별 게이트를 검토한다 (4-3의 20 epoch 탈락 원인 확인) | 별도 이슈로 진행 |
| MLflow 기록 | 프론트 Registry 화면용으로 `architecture`, `val_wape` 등을 기록하고, 예측 구간(`confidence_interval_95`)을 계산할 수 있게 플랫폼별 검증 오차 분포를 함께 저장 | 예정 (백엔드와 키 이름 합의 필요) |

- 재학습 후 품절은 seed에 따라 크게 흔들린다. 단일 seed 결과로 판단하면 안 된다.

## 부록 : 재현 방법

`scripts/validate_sales_data.py` 하나로 재현할 수 있다. 세 군데만 바꿔서 실행한다.

1. `build_model()`의 층 구성을 비교할 모델로 바꾼다 (1장의 구조).
2. `SEED`를 바꾼다. 네 모델 모두 42~46, 1차·2차 변경안은 7과 123도 돌렸다.
3. 재학습 설정 비교(4-3)를 다시 보려면 `main()`의 재학습 설정을 `for epochs, lr in [(10, 1e-4), (30, 1e-3), (20, 3e-4)]`로 바꾼다.

```bash
source .venv/bin/activate
python scripts/validate_sales_data.py
```

**확인이 끝나면 `SEED`는 42로, 재학습 설정은 원래대로 되돌린다.** 이슈 #1의 PR에는 `build_model()` 변경만 들어가야 한다.

**출력 읽는 법**
- `[1]` : 검증 WAPE, 학습-검증 차이, 정상 구간 최대
- `[2]` : 드리프트 배치 판정
- `[4]` : 재학습 설정별 승격 여부, 품절, 과잉 입고
- "승격 반영 품절"은 미승격된 seed에 `[4]`의 "재학습 전 모델" 품절을 넣어 계산했다.

**결과 예시** (2차 변경안, seed 42)
- 검증 WAPE 8.9%, 학습-검증 차이 +0.7%p, 정상 구간 최대 14.8%, 브랜디 드리프트 24.5%
- 10 epoch 재학습 후 품절 38개, 과잉 입고 161개

**비교 스크립트로 한 번에 재현하기**

`scripts/run_experiments.py`는 위 절차를 코드 수정 없이 실행한다. 모델 이름과 seed만 넘기면 결과를 JSON 한 줄로 출력한다.

```bash
SEED=42 RETRAIN_GRID="10:1e-4,30:1e-3,20:3e-4" python scripts/run_experiments.py gru_drop
```

- 모델 이름 : `baseline`(기존안), `gru`(1차 변경안), `gru_drop`(2차 변경안), `gru_drop01x2`(참고)
- 이 문서의 원본 결과 24회는 `docs/experiments/model-comparison.jsonl`에 있다. 같은 실행 환경에서는 실행 시간(`seconds`)만 달라진다.
