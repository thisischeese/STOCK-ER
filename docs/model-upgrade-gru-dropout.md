# 판매량 예측 모델 업그레이드 : 2차 변경안 (GRU 2층 + Dropout 0.2)

- 작성일 : 2026-10-02 / 브랜치 : `feature/aiops`
- 대상 모델 : 2차 변경안 `GRU(32) → Dropout(0.2) → GRU(16)`
- 비교 대상
  - 기존안 : 스켈레톤 LSTM 3층
  - 1차 변경안 : 현재 `scripts/validate_sales_data.py`에 들어 있는 모델
- 실험 : `scripts/validate_sales_data.py`와 같은 평가 절차, seed 42~46 (모델당 5회, 재현 방법은 부록)

## 요약

- **선택한 모델** : 2차 변경안 + 재학습 정책 10 epoch / 학습률 1e-4
- **선택 이유** : AIOps 루프가 해야 하는 일을 가장 안정적으로 해낸다.
  - 정상일 때 오탐하지 않는다 (5 seed 모두 운영 게이트 통과).
  - 변화가 오면 확실히 잡는다 (최악의 seed에서도 드리프트 감지 여유 +3.7%p, 세 모델 중 가장 큼).
  - 재학습 후 품절이 가장 적고 정확도가 가장 높다 (품절 중앙값 41개, 다음 21일 WAPE 9.3%).
- **감수한 것**
  - 평소 정확도는 1차 변경안이 약간 높다 (검증 WAPE 8.58% vs 8.76%).
  - 과잉 입고는 1차 변경안보다 21일에 32개 많다.
- **API 영향 없음** : 입력(20일 × 11개 피처), 출력, 스케일러, loss가 기존안과 같다.
- **정정** : 처음 공유한 "재학습 후 품절 88개 → 38개(-57%)"는 seed 42 한 번의 결과였다. 5개 seed로 보면 기존안 대비 품절 평균은 거의 같다 (62.8 → 71.6, 중앙값은 57 → 41). 대신 과잉 입고가 228 → 147개로 줄어서, **품절과 과잉을 합친 재고 오차가 291개 → 219개로 25% 줄었다.**

| 지표 (5 seed 평균) | 기존안 | 1차 변경안 | **2차 변경안** |
|---|---|---|---|
| 파라미터 | 17,377 | 7,009 | 7,009 |
| 검증 WAPE | 9.75% ± 0.64 | **8.58% ± 0.05** | 8.76% ± 0.20 |
| 학습-검증 차이 (과적합) | +1.48%p (최대 2.28) | **+0.39%p** (최대 0.66) | +0.75%p (최대 0.83) |
| 정상 구간 21일 WAPE 최대 (오탐 위험) | 19.5% (최대 27.9) | **14.0%** (최대 14.7) | 14.9% (최대 15.4) |
| 브랜디 드리프트 배치 WAPE (감지) | 25.7% (최소 21.7) | 23.8% (최소 21.1) | **26.1% (최소 23.7)** |
| 운영 게이트 전부 통과 | 4/5 seed | 5/5 | 5/5 |
| 재학습 후 품절 (평균 / 중앙값) | 62.8 / 57 | 92.0 / 66 | 71.6 / **41** |
| 재학습 후 과잉 입고 (평균) | 228.0 | **115.4** | 147.0 |
| 재학습 후 다음 21일 WAPE | 9.9% | 10.5% | **9.3%** |

재학습 결과는 10 epoch / 1e-4 기준이며, 이 설정에서는 세 모델 모두 5번 중 5번 승격됐다.

## 1. 변경 이력 : 왜 바꿨나

```
기존안      Input(20, 11) → LSTM(32) → LSTM(32) → LSTM(16)                      → Dense(16, relu) → Dense(1)   17,377 params
1차 변경안  Input(20, 11) → GRU(32) → Dropout(0.1) → GRU(16) → Dropout(0.1)     → Dense(16, relu) → Dense(1)    7,009 params
2차 변경안  Input(20, 11) → GRU(32) → Dropout(0.2) → GRU(16)                    → Dense(16, relu) → Dense(1)    7,009 params
```

| 단계 | 바꾼 내용 | 이전 버전의 문제 (5 seed 근거) | 바꾼 결과 |
|---|---|---|---|
| 기존안 → 1차 변경안 | LSTM 3층을 GRU 2층으로 줄이고, 층마다 Dropout 0.1을 넣었다 | 학습 시퀀스 1,692개에 비해 모델이 컸다 (파라미터 17,377개). 그래서 seed에 따라 과적합(학습-검증 차이 최대 2.28%p)과 오탐(정상 구간 최대 27.9%)이 나왔다. | 과적합과 오탐이 사라졌고 정확도가 가장 안정적이다 (검증 WAPE 8.58% ± 0.05). |
| 1차 변경안 → 2차 변경안 | Dropout을 두 GRU 사이 한 곳에만 두고 0.2로 높였다. 마지막 GRU 뒤의 Dropout은 없앴다. | 최악의 seed에서 브랜디 드리프트 배치 WAPE가 21.1%로, 임계값 20%를 1.1%p 차이로 겨우 넘었다. 드리프트가 조금만 약했어도 놓쳤을 수 있다. | 감지 여유가 최악 seed에서도 +3.7%p로 커졌고, 재학습 후 품절 중앙값이 66개 → 41개로 줄었다. |

## 2. 2차 변경안 구조 상세 (기존안 대비)

| 변경 | 내용 | 이유 |
|---|---|---|
| LSTM → GRU | LSTM은 게이트 3개와 별도의 셀 상태를 쓰고, GRU는 게이트 2개로 단순하다. 같은 32유닛이라도 첫 층 파라미터가 5,632개에서 4,320개로 23% 적다. | 입력이 20일로 짧아 LSTM의 긴 기억 능력이 크게 필요하지 않다. |
| 3층 → 2층 | 가운데 LSTM(32) 층을 없앴다. | 샘플 1개당 파라미터가 10.3개에서 4.1개로 줄어 과적합 위험이 낮아진다. |
| Dropout 0.2 | 학습할 때만 첫 GRU 출력의 20%를 무작위로 0으로 만든다. 서빙(추론)할 때는 꺼져 있어서 같은 입력이면 항상 같은 예측이 나온다. | 특정 신호에만 기대지 않게 만든다. 재학습(48건) 때도 똑같이 적용돼 작은 데이터에 과하게 맞추는 것을 막는다. |

**그대로 둔 것** : 입력 20일 × 11개 피처, 출력(다음 날 판매 수량), 스케일러(학습 구간에서 한 번만 fit), loss MAE, Adam 1e-3, batch 32, EarlyStopping(patience 15, 최적 가중치 복원), `SEED`, `TRAIN_RATIO`, `WINDOW = 21`, `DRIFT_THRESHOLD = 0.20`. 그래서 `/predict` API와 업로드 CSV 형식에는 영향이 없다.

## 3. AIOps 관점의 평가 기준

| 지표 | 운영에서의 의미 | 통과 기준 |
|---|---|---|
| 검증 WAPE | 평소 예측 정확도 | 7일 전 값을 그대로 쓰는 방법(14.7%)보다 낮을 것 |
| 학습-검증 차이 | 과적합 여부 (학습 데이터만 외웠는지) | 2%p 이하 |
| 정상 구간 21일 WAPE 최대 | 정상인데 드리프트로 판정할 위험 (불필요한 재학습) | 20% 미만 |
| 브랜디 드리프트 배치 WAPE | 실제 변화를 잡아내는지 | 브랜디만 20% 초과 |
| 감지 여유 / 오탐 여유 | 임계값 20%에서 얼마나 떨어져 있는지 (가장 나쁜 seed 기준) | 클수록 안전 |
| 재학습 승격률 | 재학습한 모델이 실제로 배포되는지 | 높을수록 운영을 예측하기 쉽다 |
| 재학습 후 품절 / 과잉 입고 | 비즈니스 결과 (다음 21일 브랜디, 사전 입고 = 예측 × 1.1) | 비용 비율로 판단 (5장) |

## 4. 결과 (seed 42~46)

### 4-1. 드리프트 판정 여유 (가장 나쁜 seed 기준)

| 모델 | 감지 여유 (브랜디 WAPE - 20%) | 오탐 여유 (20% - 정상 구간 최대) | 판단 |
|---|---|---|---|
| 기존안 | +1.7%p | **-7.9%p** (seed 44에서 오탐) | 정상인데 드리프트로 판정할 수 있음 |
| 1차 변경안 | **+1.1%p** | +5.3%p | 드리프트를 겨우 잡음 |
| 2차 변경안 | **+3.7%p** | +4.6%p | 양쪽 모두 여유 있음 |

드리프트를 놓치면 재학습이 일어나지 않는다. 그러면 다음 21일 품절이 평균 262~315개로, 재학습했을 때(63~92개)의 3배 이상이 된다. 그래서 감지 여유는 그 자체로 비즈니스 가치가 있다.

정확도가 가장 높은 1차 변경안이 감지 여유는 가장 작았다. README가 경고한 "입력을 너무 잘 따라가는 모델은 드리프트를 놓칠 수 있다"와 같은 방향의 결과다.

보조 시나리오(바이럴, 변동 폭 확대)는 세 모델 모두 브랜디 WAPE 약 29%로 쉽게 감지해서 차이가 없었다. 모델 간 차이는 브랜디 빠른 배송 입점 시나리오에서만 드러났다.

### 4-2. 재학습 정책별 결과 (다음 21일 브랜디)

재학습 데이터는 최근 41행(플랫폼별)이다. 학습에 48건(16일 × 3개 플랫폼), 승격 게이트 검증에 15건(5일 × 3개 플랫폼)을 쓴다. 게이트에서 탈락하면 기존 모델이 계속 서비스되므로, 아래 "승격 반영 품절"은 탈락한 seed에 기존 모델의 품절을 넣어 계산했다.

| 모델 | 재학습 설정 | 승격 | 품절 (승격 반영) | 과잉 입고* | 다음 21일 WAPE* |
|---|---|---|---|---|---|
| 2차 변경안 | **10 epoch / 1e-4** | **5/5** | **71.6** (중앙값 41) | 147.0 | 9.3% |
| 2차 변경안 | 20 epoch / 3e-4 | 1/5 | 193.6 | 371.8 | 7.6% |
| 2차 변경안 | 30 epoch / 1e-3 | 3/5 | 117.4 | 244.6 | 7.7% |
| 1차 변경안 | 10 epoch / 1e-4 | 5/5 | 92.0 | 115.4 | 10.5% |
| 1차 변경안 | 30 epoch / 1e-3 | 5/5 | 80.4 | 121.2 | 9.9% |
| 기존안 | 10 epoch / 1e-4 | 5/5 | 62.8 | 228.0 | 9.9% |
| 기존안 | 30 epoch / 1e-3 | 4/5 | 57.8 | 341.4 | 9.7% |

\* 과잉 입고와 다음 21일 WAPE는 재학습한 모델 기준이다 (승격 여부는 반영하지 않음).

- 재학습을 세게 할수록(20~30 epoch) 브랜디 정확도는 좋아지지만, 게이트에서 자주 탈락해 실제로는 기존 모델이 남는다.
- 예를 들어 2차 변경안 + 20 epoch는 다음 21일 브랜디 WAPE가 7.6%로 가장 좋았지만, 게이트 구간에서는 5번 중 4번 기존 모델보다 나빠 승격되지 않았다.
- 게이트는 세 플랫폼 전체를 보고 비즈니스 지표는 브랜디만 본다. 그래서 강한 재학습이 드리프트가 없는 지그재그와 에이블리의 예측을 흔들었을 가능성이 있다 (추정, 7장에서 확인 예정).
- 10 epoch / 1e-4는 세 모델 모두 5/5 승격으로, 운영 결과를 가장 예측하기 쉬운 정책이다. 스켈레톤의 기본값(`FINE_TUNE_EPOCHS = 10`, `FINE_TUNE_LR = 1e-4`)과도 같다.

## 5. 왜 2차 변경안을 선택했나

AIOps 루프가 맡은 일의 순서대로 기준을 세웠다.
1. 정상일 때는 조용하고 (오탐 없음)
2. 변화가 오면 반드시 잡고 (드리프트 감지)
3. 재학습 후 빨리 회복하고 (품절 감소)
4. 그 결과가 예측 가능하게 배포될 것 (승격)

| 기준 | 기존안 | 1차 변경안 | 2차 변경안 |
|---|---|---|---|
| ① 오탐·과적합 없이 운영 게이트 통과 | 4/5 seed | 5/5 | 5/5 |
| ② 드리프트 감지 여유 (최악 seed) | +1.7%p | +1.1%p | **+3.7%p** |
| ③ 재학습 후 품절 (중앙값 / 평균) | 57 / 62.8 | 66 / 92.0 | **41** / 71.6 |
| ③ 재학습 후 다음 21일 WAPE | 9.9% | 10.5% | **9.3%** |
| ④ 재학습 승격 (10 epoch / 1e-4) | 5/5 | 5/5 | 5/5 |

**선택 근거**
- **기존안은 ①에서 제외했다.** 학습할 때마다 seed 운에 따라 과적합되고 오탐하는 모델이 나올 수 있다 (seed 44).
- **1차와 2차를 가른 것은 ②다.**
  - 1차 변경안은 최악의 seed에서 드리프트를 1.1%p 차이로 겨우 잡았다.
  - 드리프트를 놓치면 재학습이 돌지 않아 다음 21일 품절이 3배 이상 늘어난다.
  - AIOps에서는 "평소에 조금 더 정확한 모델"보다 "변화를 놓치지 않는 모델"이 더 중요하다고 판단했다.
- **③에서도 2차 변경안이 앞선다.** 재학습 후 품절 중앙값이 41개(1차 66개), 다음 21일 WAPE가 9.3%(1차 10.5%)로 회복이 가장 빠르다.
- **재학습 정책은 10 epoch / 1e-4로 정했다.** 2차 변경안에서 승격이 5/5로 안정적인 유일한 설정이다.

**감수한 것**
- 평소 정확도 : 검증 WAPE가 1차 변경안보다 0.18%p 높다 (8.76% vs 8.58%).
- 과잉 입고 : 1차 변경안보다 21일에 32개 많다 (147개 vs 115개).
- 재고 오차 합계만 보면 1차 변경안 + 30 epoch 재학습(201.6개)이 2차 변경안 + 10 epoch(218.6개)보다 약간 적다. 2차를 고른 것은 재고 비용을 최소화하는 것보다 드리프트를 확실히 잡는 것을 우선했기 때문이다.
- 재학습 후 품절은 seed에 따라 27~201개로 흔들린다 (1차 변경안도 59~186개).

**재고 비용으로 본 비교** (승격이 5/5로 안정적인 조합만, 5 seed 평균)
- `k = 품절 1개의 비용 ÷ 과잉 입고 1개의 비용`으로 두고, 비용 = 품절 × k + 과잉으로 계산했다.

| k 범위 | 재고 비용이 가장 낮은 조합 |
|---|---|
| k < 2.9 | 1차 변경안 + 30 epoch / 1e-3 (k < 0.5면 1차 변경안 + 10 epoch) |
| 2.9 ≤ k < 9.2 | 2차 변경안 + 10 epoch / 1e-4 |
| k ≥ 9.2 | 기존안 + 10 epoch / 1e-4 (단, ①에서 제외) |

**다시 검토할 조건**
- 팀이 품절 1개의 비용을 과잉 1개 비용의 2.9배보다 작다고 판단하면, 1차 변경안 + 30 epoch를 다시 검토한다. 의류는 남은 재고를 할인 처분할 때 손실이 크므로 이 판단은 팀 합의가 필요하다.
- 다른 드리프트 시나리오에서 감지 여유의 순서가 뒤집히면 다시 검토한다.

## 6. 과적합과 과잉 입고는 다른 문제다

### 과적합 (모델 품질 문제)

- **정의** : 학습 데이터를 외워서 처음 보는 데이터에서 성능이 떨어지는 현상이다. 학습 WAPE와 검증 WAPE의 차이로 확인한다.
- **기존안에서 실제로 나타났다** : seed 44에서 차이가 2.28%p로 기준(2%p)을 넘었다. 같은 seed에서 정상 구간 최대 WAPE가 27.9%까지 올라가, 정상 데이터인데도 드리프트로 판정됐다(오탐). 운영에서는 불필요한 재학습이 계속 돌게 된다.
- **해결** : 구조를 바꿔서 해결했다. 파라미터를 60% 줄이고 Dropout 0.2를 넣었다. EarlyStopping 최적 가중치 복원과 warm start 재학습(낮은 학습률, 짧은 epoch)은 원래 설정을 유지했다.
- **결과** : 2차 변경안은 5개 seed 모두 차이가 0.64~0.83%p, 정상 구간 최대가 14.8~15.4%였다. seed에 따른 흔들림도 크게 줄었다 (정상 구간 최대의 표준편차 4.4 → 0.2).

### 과잉 입고 (재고 운영 결과)

- **정의** : 사전 입고량(예측 × 1.1, 올림)이 실제 판매보다 많았던 수량의 합이다. 모델 품질 지표가 아니라 재고 정책의 결과다.
- **대부분은 의도된 안전재고다** : 다음 21일 브랜디 실제 판매는 2,539개다. 예측이 완벽해도 10% 안전재고 때문에 과잉 입고가 263개 생긴다. 10 epoch 재학습 후 세 모델의 과잉 입고(115~228개)는 모두 이보다 적다.
- **모델이 만드는 부분은 수준을 따라가는 속도다** : 브랜디 판매가 빠른 배송 입점으로 일평균 43개 → 112개 → 121개로 뛰었다. 재학습 강도에 따라 모델이 새 수준을 얼마나 따라잡는지가 달라진다.
  - 약하게 따라가면 품절이 늘고 과잉이 준다.
  - 세게 따라가면 품절이 줄고 과잉이 는다.
  - 이건 과적합이 아니라 품절과 과잉을 맞바꾸는 문제이고, 5장의 비용 비율로 판단한다.

## 7. 운영에서 달라지는 점과 남은 작업

| 영역 | 내용 | 상태 |
|---|---|---|
| API | 입출력이 같아서 변경 없음 | 해당 없음 |
| 드리프트 감지 | 임계값 20% 유지. 감지 여유(최악 +3.7%p)와 오탐 여유(+4.6%p) 모두 확보 | 실험 완료 |
| 재학습 정책 | warm start, 10 epoch / 1e-4 유지 | 실험 완료 |
| 승격·롤백 | 승격 시 기존 Production을 Archived로 내려 Production을 1개로 유지 (`archive_existing_versions=True`) | HAIC 서빙에 반영·검증 완료 |
| 재배포 반영 | 승격 직후 서빙 캐시를 비워 다음 요청부터 새 모델이 응답 (`invalidate_cache()`) | HAIC 서빙에 반영·검증 완료 |
| 모델 코드 교체 | `scripts/validate_sales_data.py`의 `build_model()`을 2차 변경안으로 교체 (현재 1차 변경안) | 팀 합의 후 진행 |
| 판매량 서빙 이식 | 현재 서빙 앱은 HAIC 주가 모델이다. 판매량 모델로 옮길 때 게이트를 "WAPE 20% 이하 + 기존 모델 이하"로 바꾸고, 플랫폼별 게이트를 검토한다 (4-2의 20 epoch 탈락 원인 확인) | 예정 |
| MLflow 기록 | 프론트 Registry 화면용으로 `architecture`, `val_wape` 등을 기록하고, 예측 구간(`confidence_interval_95`)을 계산할 수 있게 플랫폼별 검증 오차 분포를 함께 저장 | 예정 (백엔드와 키 이름 합의 필요) |

**한계**
- 합성 데이터 1종과 드리프트 시나리오 1개(브랜디 빠른 배송 입점)만으로 평가했다.
- 재학습 후 품절은 seed에 따라 크게 흔들린다. 단일 seed 결과로 판단하면 안 된다.

## 부록 : 재현 방법

`scripts/validate_sales_data.py` 하나로 재현할 수 있다. 세 군데만 바꿔서 실행한다.

1. `build_model()`의 층 구성을 비교할 모델로 바꾼다 (1장의 구조).
2. `SEED`를 42~46 중 하나로 바꾼다.
   - README는 공정 비교를 위해 SEED를 고정하라고 한다.
   - 여기서는 seed 운을 확인하려고, 세 모델 모두 같은 5개 seed로 바꿔 가며 돌렸다.
3. `main()`의 재학습 설정을 `for epochs, lr in [(10, 1e-4), (30, 1e-3), (20, 3e-4)]`로 바꾼다.

```bash
source .venv/bin/activate
python scripts/validate_sales_data.py
```

**출력 읽는 법**
- `[1]` : 검증 WAPE, 학습-검증 차이, 정상 구간 최대
- `[2]` : 드리프트 배치 판정
- `[4]` : 재학습 설정별 승격 여부, 품절, 과잉 입고
- 4-2의 "승격 반영 품절"은 미승격된 seed에 `[4]`의 "재학습 전 모델" 품절을 넣어 계산했다.

**결과 예시** (2차 변경안, seed 42)
- 검증 WAPE 8.9%, 학습-검증 차이 +0.7%p, 정상 구간 최대 14.8%, 브랜디 드리프트 24.5%
- 10 epoch 재학습 후 품절 38개, 과잉 입고 161개
- 이 값은 처음 공유한 표와 같다.

실험에 쓴 비교 스크립트와 원본 결과(15회)는 저장소에 넣지 않았다.
